## Как поддерживается
- **Новая нода**: все три кладёт шаг `operator_access` мастера из `operator_keys.pub`
  (плюс ключ оператора дублируется провижином через `--vova-pubkey` = `SSH_KEY.pub`;
  добавление идемпотентно, дублей не будет).
- **Приватную половину `fleet-auto`** новой ноде-члену кластера скопировать
  **с действующего узла кластера** (`rsync`/`scp` узел→узел) в `/home/vova/.ssh/id_nodes`
  и `/root/.ssh/id_rsa`, иначе GD/WD/`dispatcherctl` с неё не ходят. В репозитории и на
  рабочей станции приватной половины НЕТ намеренно — в `Servers_keys/fleet-auto/` лежит
  только `.pub` для сверки отпечатка. Если все узлы кластера потеряны одновременно —
  генерируется новый ключ автоматики и раскладывается заново (вход к тому моменту есть
  по ключу оператора).
  ⚠️ Рядом обязателен **свой** `.pub`: `asyncssh` сверяет пару и падает
  `ValueError: Public key mismatch`, если `.pub` от старого ключа.
- **Новый оператор / ротация**: добавить строку в `operator_keys.pub`, прогнать
  `operator_access` по флоту, обновить этот реестр.
